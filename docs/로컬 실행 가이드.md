# 로컬 실행 및 테스트 가이드

MySQL 컨테이너는 실행 목적에 따라 자동으로 준비됩니다.

> **사전 준비:** 애플리케이션과 테스트 모두 MySQL 컨테이너를 사용하므로 Docker 실행 환경이 준비되어 있어야 합니다. (예: Docker Desktop 설치 및 실행)

| 실행 목적 | 사용하는 MySQL | DB 접속 정보 |
|---|---|---|
| 애플리케이션 실행 | `compose.yaml`의 MySQL 컨테이너 (데이터 유지) | [Spring Boot Docker Compose 지원](https://docs.spring.io/spring-boot/reference/features/dev-services.html#features.dev-services.docker-compose)을 통해 자동 구성 |
| 테스트 실행 | 테스트 실행 시 새로 띄우는 MySQL 컨테이너 (테스트 후 삭제) | `@ServiceConnection`을 통해 자동 구성 (참고: [Testcontainers](https://docs.spring.io/spring-boot/reference/testing/testcontainers.html)) |

## 1. 애플리케이션 실행

IntelliJ에서 `TicketReservationApiApplication`을 실행하거나, 터미널에서 다음 명령을 실행합니다. (Windows의 경우 `./gradlew` 대신 `gradlew.bat` 사용)
```bash
./gradlew bootRun
```

- 실행 시 MySQL 컨테이너가 자동으로 시작되고, **healthy 상태가 된 뒤** 애플리케이션이 기동됩니다.
- 애플리케이션이 컨테이너를 시작한 경우, 정상 종료하면 컨테이너도 함께 중지됩니다. (데이터는 볼륨에 유지됩니다.)
- 컨테이너가 이미 실행 중이었다면 그대로 사용하고, 종료 시에도 중지하지 않습니다.
- Docker Compose 지원은 로컬 개발 전용(`developmentOnly`)이며, 빌드된 jar에는 포함되지 않습니다.

기본값 대신 다른 계정·비밀번호를 쓰려면 실행 전에 `.env`를 만들어 값을 수정합니다.
```bash
cp .env.example .env
```

> `.env`의 계정·비밀번호 등 MySQL 초기 설정(`MYSQL_*`)은 MySQL 볼륨이 **처음 생성될 때만** 적용됩니다.

## 2. 테스트 실행

```bash
./gradlew test
```

- Testcontainers가 테스트용 MySQL 컨테이너를 자동으로 띄우고, 테스트 종료 후 컨테이너는 Testcontainers의 생명주기에 따라 정리됩니다.
- `compose.yaml`의 MySQL과는 **별개의 컨테이너**이므로, 로컬 개발 DB의 데이터에 영향을 주지 않고 `.env` 설정과도 무관합니다.
- DB가 필요한 테스트 클래스에는 `@Import(TestcontainersConfiguration.class)`를 추가합니다.

## 3. 환경변수와 DB 접속 정보

### 환경변수 구분

환경변수는 **사용하는 쪽이 다르기 때문에** 두 묶음으로 나뉩니다. 모두 기본값이 있어 필요할 때만 설정합니다.

| 사용처 | 변수 | 설정 위치 | 설명 |
|---|---|---|---|
| Docker Compose (MySQL 컨테이너) | `MYSQL_ROOT_PASSWORD`, `MYSQL_USER`, `MYSQL_PASSWORD` | 프로젝트 루트 `.env` (선택) | Compose가 `compose.yaml`의 `${...}`를 치환할 때만 읽습니다. |
| Spring Boot | `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | 셸 환경변수 등 (선택) | `application.yml`의 `${...}`를 해석할 때 사용합니다. (빌드된 jar 실행 시) |

로컬 기본값은 다음과 같으며, Compose와 Spring Boot의 값이 서로 맞춰져 있습니다.

| Docker Compose | Spring Boot | 기본값 |
|---|---|---|
| - | `DB_URL` | `jdbc:mysql://localhost:3307/ticketing` |
| `MYSQL_USER` | `DB_USERNAME` | `ticketing_app` |
| `MYSQL_PASSWORD` | `DB_PASSWORD` | `local-app-password` |
| `MYSQL_ROOT_PASSWORD` | - | `local-root-password` |

> 기본값은 **로컬 개발 전용**입니다. 운영 등 다른 환경에서는 반드시 환경변수로 값을 지정하세요.

- `.env`는 Docker Compose 전용입니다. Spring Boot는 `.env`를 읽지 않습니다.

### DB 접속 정보 적용 우선순위

자동 구성된 DB 접속 정보가 `application.yml`의 접속 관련 설정보다 **우선순위가 높습니다.**

따라서 애플리케이션·테스트 실행 시에는 `application.yml`의 `spring.datasource.url`, `username`, `password`나 `DB_*` 환경변수를 바꿔도 **반영되지 않습니다.**

| 실행 방식 | DB 접속 정보 (`url`, `username`, `password`) | 그 외 `application.yml` 설정 (커넥션 풀, 서버 포트 등) |
|---|---|---|
| 애플리케이션 실행 (IntelliJ, `bootRun`) | `compose.yaml` / `.env` 값 | 적용됨 |
| 테스트 실행 | Testcontainers가 띄운 컨테이너 값 | 적용됨 |
| 빌드된 jar 실행 (운영 등) | `application.yml` / `DB_*` 환경변수 | 적용됨 |

- 로컬 MySQL의 계정·비밀번호를 바꾸려면 `application.yml`이 아니라 `.env`의 `MYSQL_USER`, `MYSQL_PASSWORD`를 수정합니다.
- 다른 MySQL 서버에 접속하는 등 `application.yml` / `DB_*` 값을 사용해야 한다면 실행 환경변수에 `SPRING_DOCKER_COMPOSE_ENABLED=false`를 설정합니다.
  이 경우 MySQL 컨테이너는 자동으로 실행되지 않습니다.
