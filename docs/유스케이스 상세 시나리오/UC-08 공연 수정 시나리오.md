# 공연 수정 시나리오

> 공연 정보 수정(UC-08)이 예약 신청(UC-09), 다른 공연 정보 수정, 예약 만료 처리(UC-13)와 동시에 실행되는 상황을 정리합니다. 실패 시나리오는 오류 반환 외에 별도 복구 처리가 필요한 경우만 작성합니다.

## 1. 같은 공연에 대한 시나리오

### UC-08-01. 예약 신청 중 공연 정보 수정

- **액터:** 회원, 관리자
- **선행 조건:** 판매 기간인 공연이 존재한다. 회원의 예약 신청이 처리 중이다.
- **성공 시나리오**
  1. 관리자가 같은 공연의 정보 수정을 요청한다.
  2. 시스템은 예약 처리가 끝날 때까지 수정 요청을 대기시킨다.
  3. 시스템은 해당 공연에서 결제 제한 시각이 지난 결제 대기 예약을 만료 처리한다.
  4. 시스템은 예약이 반영된 예약 수량을 기준으로 수정 요청을 검증한다.
  5. 시스템은 공연 정보를 수정한다.
- **확장**
  - **2a. 대기 시간이 제한 시간을 넘긴 경우:** 시스템은 수정 요청을 거절한다.
  - **4a. 변경하려는 총 판매 수량이 예약 수량 합계보다 적어진 경우:** 시스템은 수정 요청을 거절한다.
  - **4b. 첫 예약이 생겨 공연 일시 또는 판매 시작 일시를 변경할 수 없게 된 경우:** 시스템은 수정 요청을 거절한다.
- **실패 시나리오**
  - **4a, 4b. 3에서 만료 처리한 뒤 수정 요청을 거절한 경우**
    1. 시스템은 3의 만료 처리를 함께 취소한다. 예약 상태와 예약 수량은 요청 전 상태로 남는다.
    2. 예약 만료 처리 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.

### UC-08-02. 공연 정보 수정 중 공연 정보 수정

- **액터:** 관리자 A, 관리자 B
- **선행 조건:** 공연이 존재한다. 관리자 A의 공연 정보 수정이 처리 중이다.
- **성공 시나리오**
  1. 관리자 B가 같은 공연의 정보 수정을 요청한다.
  2. 시스템은 관리자 A의 수정 처리가 끝날 때까지 관리자 B의 요청을 대기시킨다.
  3. 시스템은 해당 공연에서 결제 제한 시각이 지난 결제 대기 예약을 만료 처리한다.
  4. 시스템은 관리자 B가 조회한 이후 다른 수정이 반영됐는지 확인한다.
  5. 시스템은 공연 정보를 수정한다.
- **확장**
  - **2a. 대기 시간이 제한 시간을 넘긴 경우:** 시스템은 수정 요청을 거절한다.
  - **4a. 관리자 A의 수정이 먼저 반영된 경우:** 시스템은 관리자 B의 수정 요청을 거절한다.
- **실패 시나리오**
  - **4a. 3에서 만료 처리한 뒤 수정 요청을 거절한 경우**
    1. 시스템은 3의 만료 처리를 함께 취소한다. 예약 상태와 예약 수량은 요청 전 상태로 남는다.
    2. 예약 만료 처리 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.

### UC-08-03. 예약 만료 중 공연 정보 수정

- **액터:** 예약 만료 처리 스케줄러, 관리자
- **선행 조건:** 결제 제한 시각이 지난 결제 대기 예약이 있는 공연이 존재한다. 스케줄러가 해당 공연의 만료 처리 중이다.
- **성공 시나리오**
  1. 관리자가 같은 공연의 정보 수정을 요청한다.
  2. 시스템은 만료 처리가 끝날 때까지 수정 요청을 대기시킨다.
  3. 시스템은 해당 공연에서 결제 제한 시각이 지난 결제 대기 예약을 만료 처리한다.
  4. 시스템은 만료가 반영된 예약 수량을 기준으로 수정 요청을 검증한다.
  5. 시스템은 공연 정보를 수정한다.
- **확장**
  - **2a. 대기 시간이 제한 시간을 넘긴 경우:** 시스템은 수정 요청을 거절한다.
  - **4a. 만료로 예약 수량 합계가 줄어든 경우:** 시스템은 줄어든 예약 수량 합계를 기준으로 총 판매 수량 변경 가능 여부를 판단한다.
  - **4b. 만료로 남은 예약이 없어진 경우:** 시스템은 공연 일시 또는 판매 시작 일시 변경을 허용한다.
- **실패 시나리오**
  - **2b. 스케줄러의 만료 처리가 실패한 경우**
    1. 시스템은 스케줄러가 변경한 예약 상태와 잔여 판매 수량을 모두 취소한다.
    2. 시스템은 3부터 진행한다. 스케줄러가 만료하지 못한 예약은 3에서 만료 처리한다.
  - **3a. 공연 정보 수정의 만료 처리가 실패한 경우**
    1. 시스템은 공연 정보 수정에서 변경한 예약 상태와 잔여 판매 수량을 모두 취소하고 수정 요청을 실패 처리한다.
    2. 예약 만료 처리 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.

## 2. 다른 공연에 대한 시나리오

> 다른 공연은 서로의 재고와 예약에 영향을 주지 않으므로 처리 순서와 관계없이 독립적으로 실행됩니다. 따라서 동일한 동시 실행 상황은 하나의 시나리오에만 정의하고, 다른 시나리오에서는 해당 시나리오를 참조합니다.

### UC-08-04. 다른 공연 예약 신청 중 공연 정보 수정

- **액터:** 회원, 관리자
- **선행 조건:** 판매 기간인 서로 다른 공연 X와 Y가 존재한다. 회원의 공연 X 예약 신청이 처리 중이다.
- **성공 시나리오**
  1. 관리자가 공연 Y의 정보 수정을 요청한다.
  2. 시스템은 회원의 예약 처리를 기다리지 않고 수정 요청을 처리한다.
  3. 시스템은 공연 Y에서 결제 제한 시각이 지난 결제 대기 예약을 만료 처리한다.
  4. 시스템은 공연 Y의 예약 수량을 기준으로 수정 요청을 검증한다.
  5. 시스템은 공연 Y의 정보를 수정한다.
  6. 공연 X의 예약 신청도 수정 처리를 기다리지 않고 진행된다.
- **확장**
  - **4a. 공연 정보 수정(UC-08)의 수정 요청 거절 조건에 해당하는 경우:** 시스템은 수정 요청을 거절한다.
- **실패 시나리오**
  - **4a. 3에서 만료 처리한 뒤 수정 요청을 거절한 경우**
    1. 시스템은 3의 만료 처리를 함께 취소한다. 예약 상태와 예약 수량은 요청 전 상태로 남는다.
    2. 예약 만료 처리 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.

### UC-08-05. 다른 공연 공연 정보 수정 중 공연 정보 수정

- **액터:** 관리자 A, 관리자 B
- **선행 조건:** 서로 다른 공연 X와 Y가 존재한다. 관리자 A의 공연 X 정보 수정이 처리 중이다.
- **성공 시나리오**
  1. 관리자 B가 공연 Y의 정보 수정을 요청한다.
  2. 시스템은 관리자 A의 수정 처리를 기다리지 않고 관리자 B의 수정 요청을 처리한다.
  3. 시스템은 공연 Y에서 결제 제한 시각이 지난 결제 대기 예약을 만료 처리한다.
  4. 시스템은 공연 Y의 예약 수량을 기준으로 수정 요청을 검증한다.
  5. 시스템은 공연 Y의 정보를 수정한다.
  6. 관리자 A의 공연 X 수정도 관리자 B의 수정을 기다리지 않고 진행된다.
- **확장**
  - **4a. 공연 정보 수정(UC-08)의 수정 요청 거절 조건에 해당하는 경우:** 시스템은 수정 요청을 거절한다.
- **실패 시나리오**
  - **4a. 3에서 만료 처리한 뒤 수정 요청을 거절한 경우**
    1. 시스템은 3의 만료 처리를 함께 취소한다. 예약 상태와 예약 수량은 요청 전 상태로 남는다.
    2. 예약 만료 처리 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.

### UC-08-06. 다른 공연 예약 만료 중 공연 정보 수정

- **액터:** 예약 만료 처리 스케줄러, 관리자
- **선행 조건:** 서로 다른 공연 X와 Y가 존재한다. 공연 X에 결제 제한 시각이 지난 결제 대기 예약이 있다. 스케줄러가 공연 X의 만료 처리 중이다.
- **성공 시나리오**
  1. 관리자가 공연 Y의 정보 수정을 요청한다.
  2. 시스템은 스케줄러의 만료 처리를 기다리지 않고 수정 요청을 처리한다.
  3. 시스템은 공연 Y에서 결제 제한 시각이 지난 결제 대기 예약을 만료 처리한다.
  4. 시스템은 공연 Y의 예약 수량을 기준으로 수정 요청을 검증한다.
  5. 시스템은 공연 Y의 정보를 수정한다.
  6. 스케줄러는 수정 처리를 기다리지 않고 공연 X의 예약을 만료 처리하고 잔여 판매 수량을 복구한 뒤, 다음 공연의 만료 처리를 계속한다.
- **확장**
  - **4a. 공연 정보 수정(UC-08)의 수정 요청 거절 조건에 해당하는 경우:** 시스템은 수정 요청을 거절한다.
- **실패 시나리오**
  - **4a. 3에서 만료 처리한 뒤 수정 요청을 거절한 경우**
    1. 시스템은 3의 만료 처리를 함께 취소한다. 예약 상태와 예약 수량은 요청 전 상태로 남는다.
    2. 예약 만료 처리 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.
