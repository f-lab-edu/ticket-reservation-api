# 예약 만료 시나리오

> 예약 만료 처리(UC-13)가 예약 신청(UC-09), 공연 정보 수정(UC-08), 다른 예약 만료 처리와 동시에 실행되는 상황을 정리합니다. 실패 시나리오는 오류 반환 외에 별도 복구 처리가 필요한 경우만 작성합니다.

## 1. 같은 공연에 대한 시나리오

### UC-13-01. 예약 신청 중 예약 만료

- **액터:** 회원, 예약 만료 처리 스케줄러
- **선행 조건:** 결제 제한 시각이 지난 결제 대기 예약이 있는 공연이 존재한다. 같은 공연의 예약 신청이 처리 중이다.
- **성공 시나리오**
  1. 스케줄러가 같은 공연의 만료 처리를 시작한다.
  2. 시스템은 처리 중인 공연임을 확인하고 기다리지 않고 해당 공연을 건너뛴다.
  3. 시스템은 다른 공연의 만료 처리를 계속한다.
  4. 시스템은 다음 실행에서 해당 공연의 만료 대상을 다시 확인한다.
- **확장**
  - **4a. 예약 신청이 이미 만료 처리한 경우:** 시스템은 만료할 예약이 없으므로 아무것도 변경하지 않는다.
  - **4b. 예약 신청이 거절되어 만료 처리가 취소된 경우:** 시스템은 해당 예약을 만료 처리한다.

### UC-13-02. 공연 정보 수정 중 예약 만료

- **액터:** 관리자, 예약 만료 처리 스케줄러
- **선행 조건:** 결제 제한 시각이 지난 결제 대기 예약이 있는 공연이 존재한다. 같은 공연의 공연 정보 수정이 처리 중이다.
- **성공 시나리오**

  2. 시스템은 처리 중인 공연임을 확인하고 기다리지 않고 해당 공연을 건너뛴다.
  3. 시스템은 다른 공연의 만료 처리를 계속한다.
  4. 시스템은 다음 실행에서 해당 공연의 만료 대상을 다시 확인한다.

### UC-13-03. 예약 만료 중 예약 만료

- **액터:** 서버 A의 스케줄러, 서버 B의 스케줄러
- **선행 조건:** 결제 제한 시각이 지난 결제 대기 예약이 있는 공연이 존재한다. 서버 A의 스케줄러가 해당 공연의 만료 처리 중이다.
- **성공 시나리오**
  1. 서버 B의 스케줄러가 같은 공연의 만료 처리를 시작한다.
  2. 시스템은 처리 중인 공연임을 확인하고 기다리지 않고 해당 공연을 건너뛴다.
  3. 시스템은 다른 공연의 만료 처리를 계속한다.
- **실패 시나리오**
  - **2a. 서버 A의 만료 처리가 실패한 경우**
    1. 시스템은 해당 공연의 예약 상태와 잔여 판매 수량 변경을 모두 취소한다.
    2. 서버 A 또는 서버 B의 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.

## 2. 다른 공연에 대한 시나리오

> 다른 공연은 서로의 재고와 예약에 영향을 주지 않으므로 처리 순서와 관계없이 독립적으로 실행됩니다. 따라서 동일한 동시 실행 상황은 하나의 시나리오에만 정의하고, 다른 시나리오에서는 해당 시나리오를 참조합니다.

### UC-13-04. 다른 공연 예약 신청 중 예약 만료

- **액터:** 회원, 예약 만료 처리 스케줄러
- **선행 조건:** 서로 다른 공연 X와 Y가 존재한다. 공연 Y에 결제 제한 시각이 지난 결제 대기 예약이 있다. 회원의 공연 X 예약 신청이 처리 중이다.
- **성공 시나리오, 확장, 실패 시나리오:** 예약 신청 시나리오의 UC-09-06(다른 공연 예약 만료 중 예약 신청)과 동일하다.

### UC-13-05. 다른 공연 공연 정보 수정 중 예약 만료

- **액터:** 관리자, 예약 만료 처리 스케줄러
- **선행 조건:** 서로 다른 공연 X와 Y가 존재한다. 공연 Y에 결제 제한 시각이 지난 결제 대기 예약이 있다. 관리자의 공연 X 정보 수정이 처리 중이다.
- **성공 시나리오, 확장, 실패 시나리오:** 공연 수정 시나리오의 UC-08-06(다른 공연 예약 만료 중 공연 정보 수정)과 동일하다.

### UC-13-06. 다른 공연 예약 만료 중 예약 만료

- **액터:** 서버 A의 스케줄러, 서버 B의 스케줄러
- **선행 조건:** 서로 다른 공연 X와 Y에 결제 제한 시각이 지난 결제 대기 예약이 있다. 서버 A의 스케줄러가 공연 X의 만료 처리 중이다.
- **성공 시나리오**
  1. 서버 B의 스케줄러가 공연 Y의 만료 처리를 시작한다.
  2. 시스템은 서버 A의 처리를 기다리지 않고 만료 처리를 진행한다.
  3. 시스템은 공연 Y에서 결제 제한 시각이 지난 결제 대기 예약을 만료 처리하고 잔여 판매 수량을 복구한다.
  4. 시스템은 다음 공연의 만료 처리를 계속한다.
  5. 서버 A의 공연 X 만료 처리도 서버 B의 처리를 기다리지 않고 진행된다.
