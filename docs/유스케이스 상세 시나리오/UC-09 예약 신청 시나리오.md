# 예약 신청 시나리오

> 예약 신청(UC-09)이 다른 예약 신청, 공연 정보 수정(UC-08), 예약 만료 처리(UC-13)와 동시에 실행되는 상황을 정리합니다. 실패 시나리오는 오류 반환 외에 별도 복구 처리가 필요한 경우만 작성합니다.

## 1. 같은 공연에 대한 시나리오

### UC-09-01. 예약 신청 중 예약 신청

- **액터:** 회원 A, 회원 B
- **선행 조건:** 판매 기간인 공연이 존재한다. 회원 A의 예약 신청이 처리 중이다.
- **성공 시나리오**
  1. 회원 B가 같은 공연에 예약을 요청한다.
  2. 시스템은 회원 A의 예약 처리가 끝날 때까지 회원 B의 요청을 대기시킨다.
  3. 시스템은 해당 공연에서 결제 제한 시각이 지난 결제 대기 예약을 만료 처리한다.
  4. 시스템은 회원 A의 예약이 반영된 잔여 판매 수량을 기준으로 회원 B의 예약 요청을 검증한다.
  5. 시스템은 회원 B의 예약을 생성하고 잔여 판매 수량을 차감한다.
- **확장**
  - **2a. 대기 시간이 제한 시간을 넘긴 경우:** 시스템은 예약 요청을 거절한다.
  - **4a. 회원 A의 예약으로 잔여 판매 수량이 부족해진 경우:** 시스템은 예약 요청을 거절한다.
- **실패 시나리오**
  - **4a. 3에서 만료 처리한 뒤 예약 요청을 거절한 경우**
    1. 시스템은 3의 만료 처리를 함께 취소한다. 예약 상태와 잔여 판매 수량은 요청 전 상태로 남는다.
    2. 예약 만료 처리 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.

### UC-09-02. 공연 정보 수정 중 예약 신청

- **액터:** 관리자, 회원
- **선행 조건:** 판매 기간인 공연이 존재한다. 관리자의 공연 정보 수정이 처리 중이다.
- **성공 시나리오**
  1. 회원이 같은 공연에 예약을 요청한다.
  2. 시스템은 수정 처리가 끝날 때까지 예약 요청을 대기시킨다.
  3. 시스템은 해당 공연에서 결제 제한 시각이 지난 결제 대기 예약을 만료 처리한다.
  4. 시스템은 수정된 판매 기간과 잔여 판매 수량을 기준으로 예약 요청을 검증한다.
  5. 시스템은 예약을 생성하고 잔여 판매 수량을 차감한다.
- **확장**
  - **2a. 대기 시간이 제한 시간을 넘긴 경우:** 시스템은 예약 요청을 거절한다.
  - **4a. 수정으로 판매 기간이 아니게 된 경우:** 시스템은 예약 요청을 거절한다.
  - **4b. 수정으로 잔여 판매 수량이 부족해진 경우:** 시스템은 예약 요청을 거절한다.
- **실패 시나리오**
  - **4a, 4b. 3에서 만료 처리한 뒤 예약 요청을 거절한 경우**
    1. 시스템은 3의 만료 처리를 함께 취소한다. 예약 상태와 잔여 판매 수량은 요청 전 상태로 남는다.
    2. 예약 만료 처리 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.

### UC-09-03. 예약 만료 중 예약 신청

- **액터:** 예약 만료 처리 스케줄러, 회원
- **선행 조건:** 결제 제한 시각이 지난 결제 대기 예약이 있는 공연이 존재한다. 스케줄러가 해당 공연의 만료 처리 중이다.
- **성공 시나리오**
  1. 회원이 같은 공연에 예약을 요청한다.
  2. 시스템은 만료 처리가 끝날 때까지 예약 요청을 대기시킨다.
  3. 시스템은 해당 공연에서 결제 제한 시각이 지난 결제 대기 예약을 만료 처리한다.
  4. 시스템은 만료로 복구된 잔여 판매 수량을 기준으로 예약 요청을 검증한다.
  5. 시스템은 예약을 생성하고 잔여 판매 수량을 차감한다.
- **확장**
  - **2a. 대기 시간이 제한 시간을 넘긴 경우:** 시스템은 예약 요청을 거절한다.
  - **4a. 복구된 수량으로도 잔여 판매 수량이 부족한 경우:** 시스템은 예약 요청을 거절한다.
- **실패 시나리오**
  - **2b. 스케줄러의 만료 처리가 실패한 경우**
    1. 시스템은 스케줄러가 변경한 예약 상태와 잔여 판매 수량을 모두 취소한다.
    2. 시스템은 3부터 진행한다. 스케줄러가 만료하지 못한 예약은 3에서 만료 처리한다.
  - **3a. 예약 신청의 만료 처리가 실패한 경우**
    1. 시스템은 예약 신청에서 변경한 예약 상태와 잔여 판매 수량을 모두 취소하고 예약 요청을 실패 처리한다.
    2. 예약 만료 처리 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.
  - **4a. 3에서 만료 처리한 뒤 예약 요청을 거절한 경우**
    1. 시스템은 3의 만료 처리를 함께 취소한다. 예약 상태와 잔여 판매 수량은 요청 전 상태로 남는다.
    2. 예약 만료 처리 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.

## 2. 다른 공연에 대한 시나리오

> 다른 공연은 서로의 재고와 예약에 영향을 주지 않으므로 처리 순서와 관계없이 독립적으로 실행됩니다. 따라서 동일한 동시 실행 상황은 하나의 시나리오에만 정의하고, 다른 시나리오에서는 해당 시나리오를 참조합니다.

### UC-09-04. 다른 공연 예약 신청 중 예약 신청

- **액터:** 회원 A, 회원 B
- **선행 조건:** 판매 기간인 서로 다른 공연 X와 Y가 존재한다. 회원 A의 공연 X 예약 신청이 처리 중이다.
- **성공 시나리오**
  1. 회원 B가 공연 Y에 예약을 요청한다.
  2. 시스템은 회원 A의 처리를 기다리지 않고 회원 B의 요청을 처리한다.
  3. 시스템은 공연 Y에서 결제 제한 시각이 지난 결제 대기 예약을 만료 처리한다.
  4. 시스템은 공연 Y의 잔여 판매 수량을 기준으로 예약 요청을 검증한다.
  5. 시스템은 회원 B의 예약을 생성하고 공연 Y의 잔여 판매 수량을 차감한다.
  6. 회원 A의 공연 X 예약 신청도 회원 B의 처리를 기다리지 않고 진행된다.
- **확장**
  - **4a. 공연 Y의 잔여 판매 수량이 부족한 경우:** 시스템은 예약 요청을 거절한다.
- **실패 시나리오**
  - **4a. 3에서 만료 처리한 뒤 예약 요청을 거절한 경우**
    1. 시스템은 3의 만료 처리를 함께 취소한다. 예약 상태와 잔여 판매 수량은 요청 전 상태로 남는다.
    2. 예약 만료 처리 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.

### UC-09-05. 다른 공연 공연 정보 수정 중 예약 신청

- **액터:** 관리자, 회원
- **선행 조건:** 판매 기간인 서로 다른 공연 X와 Y가 존재한다. 관리자의 공연 X 정보 수정이 처리 중이다.
- **성공 시나리오, 확장, 실패 시나리오:** 공연 수정 시나리오의 UC-08-04(다른 공연 예약 신청 중 공연 정보 수정)와 동일하다.

### UC-09-06. 다른 공연 예약 만료 중 예약 신청

- **액터:** 예약 만료 처리 스케줄러, 회원
- **선행 조건:** 판매 기간인 서로 다른 공연 X와 Y가 존재한다. 공연 X에 결제 제한 시각이 지난 결제 대기 예약이 있다. 스케줄러가 공연 X의 만료 처리 중이다.
- **성공 시나리오**
  1. 회원이 공연 Y에 예약을 요청한다.
  2. 시스템은 스케줄러의 만료 처리를 기다리지 않고 예약 요청을 처리한다.
  3. 시스템은 공연 Y에서 결제 제한 시각이 지난 결제 대기 예약을 만료 처리한다.
  4. 시스템은 공연 Y의 잔여 판매 수량을 기준으로 예약 요청을 검증한다.
  5. 시스템은 예약을 생성하고 공연 Y의 잔여 판매 수량을 차감한다.
  6. 스케줄러는 예약 처리를 기다리지 않고 공연 X의 예약을 만료 처리하고 잔여 판매 수량을 복구한 뒤, 다음 공연의 만료 처리를 계속한다.
- **확장**
  - **4a. 공연 Y의 잔여 판매 수량이 부족한 경우:** 시스템은 예약 요청을 거절한다.
- **실패 시나리오**
  - **4a. 3에서 만료 처리한 뒤 예약 요청을 거절한 경우**
    1. 시스템은 3의 만료 처리를 함께 취소한다. 예약 상태와 잔여 판매 수량은 요청 전 상태로 남는다.
    2. 예약 만료 처리 스케줄러가 다음 실행에서 해당 예약을 만료 처리한다.
