# 로컬 개발 환경

로컬에서는 MySQL을 Docker Compose로 실행하고, Spring Boot는 IntelliJ(또는 Gradle)에서 실행합니다.
DB 접속 정보에는 로컬 개발 전용 기본값이 있어 **별도 설정 없이 바로 실행할 수 있습니다.**

## 환경변수 구분

환경변수는 **사용하는 쪽이 다르기 때문에** 두 묶음으로 나뉩니다. 모두 기본값이 있어 필요할 때만 설정합니다.

| 사용처 | 변수 | 설정 위치 | 설명 |
|---|---|---|---|
| Docker Compose (MySQL 컨테이너) | `MYSQL_ROOT_PASSWORD`, `MYSQL_USER`, `MYSQL_PASSWORD` | 프로젝트 루트 `.env` (선택) | Compose가 `compose.yaml`의 `${...}`를 치환할 때만 읽습니다. |
| Spring Boot | `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | IntelliJ Run Configuration / 셸 환경변수 (선택) | `application.yml`의 `${...}`를 해석할 때 사용합니다. |

로컬 기본값은 다음과 같으며, Compose와 Spring Boot의 값이 서로 맞춰져 있습니다.

| Docker Compose | Spring Boot | 기본값 |
|---|---|---|
| - | `DB_URL` | `jdbc:mysql://localhost:3307/ticketing` |
| `MYSQL_USER` | `DB_USERNAME` | `ticketing_app` |
| `MYSQL_PASSWORD` | `DB_PASSWORD` | `local-app-password` |
| `MYSQL_ROOT_PASSWORD` | - | `local-root-password` |

> 기본값은 **로컬 개발 전용**입니다. 운영 등 다른 환경에서는 반드시 환경변수로 값을 지정하세요.

- `.env`는 Docker Compose 전용입니다. **IntelliJ에서 실행하는 Spring Boot는 `.env`를 자동으로 읽지 않습니다.**
- `.env`에서 `MYSQL_USER`, `MYSQL_PASSWORD`를 기본값과 다르게 바꿨다면, Spring Boot에도 `DB_USERNAME`, `DB_PASSWORD`를 같은 값으로 설정해야 합니다.

### DB 접속 정보가 일치하지 않으면

- 애플리케이션은 **정상적으로 기동됩니다.**
- DB를 사용하는 시점에 다음 오류로 실패합니다.
  ```
  Access denied for user 'ticketing_app'@'...' (using password: YES)
  ```
  이 오류가 보이면 Compose(`.env`)와 Spring Boot(`DB_USERNAME`, `DB_PASSWORD`)의 값이 같은지 확인하세요.

## 1. MySQL 실행
※ Docker가 설치된 상태에서 아래 단계를 진행합니다.
```powershell
docker compose up -d
docker compose ps        # STATUS가 healthy인지 확인
```

기본값 대신 다른 비밀번호를 쓰려면 실행 전에 `.env`를 만들어 값을 수정합니다.
```powershell
copy .env.example .env
```

> 비밀번호는 MySQL 볼륨이 **처음 생성될 때만** 적용됩니다.

## 2. IntelliJ에서 애플리케이션 실행

`TicketReservationApiApplication`을 바로 실행하면 됩니다.

`.env`로 기본값을 바꿨다면 `Run > Edit Configurations...`에서 `TicketReservationApiApplication` 설정을 열고,
**Environment variables**에 `DB_USERNAME=<.env의 MYSQL_USER 값>;DB_PASSWORD=<.env의 MYSQL_PASSWORD 값>`을 입력합니다.
