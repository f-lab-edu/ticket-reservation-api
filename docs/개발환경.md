# 로컬 개발 환경

로컬에서는 MySQL을 Docker Compose로 실행하고, Spring Boot는 IntelliJ(또는 Gradle)에서 환경변수로 DB 접속 정보를 전달해 실행합니다.

## 환경변수 구분

환경변수는 **사용하는 쪽이 다르기 때문에** 두 묶음으로 나뉩니다.

| 사용처 | 변수 | 설정 위치 | 설명 |
|---|---|---|---|
| Docker Compose (MySQL 컨테이너) | `MYSQL_ROOT_PASSWORD`, `MYSQL_USER`, `MYSQL_PASSWORD` | 프로젝트 루트 `.env` | Compose가 `compose.yaml`의 `${...}`를 치환할 때만 읽습니다. |
| Spring Boot | `DB_PASSWORD` (필수), `DB_URL`, `DB_USERNAME` (선택) | IntelliJ Run Configuration / 셸 환경변수 | `application.yml`의 `${...}`를 해석할 때 사용합니다. |

- `.env`는 Docker Compose 전용입니다. **IntelliJ에서 실행하는 Spring Boot는 `.env`를 자동으로 읽지 않습니다.**
- `DB_PASSWORD`에는 `.env`의 `MYSQL_PASSWORD`와 같은 값을 넣습니다.
- `DB_URL`, `DB_USERNAME`은 기본값(`jdbc:mysql://localhost:3307/ticketing`, `ticketing_app`)이 있어 보통 설정하지 않아도 됩니다.

### `DB_PASSWORD`를 설정하지 않으면

- 애플리케이션은 **정상적으로 기동됩니다.**
- DB를 사용하는 시점에 다음 오류로 실패합니다.
  ```
  Access denied for user 'ticketing_app'@'...' (using password: YES)
  ```
  이 오류가 보이면 먼저 `DB_PASSWORD` 설정 여부를 확인하세요.

## 1. MySQL 실행
※ Docker가 설치된 상태에서 아래 단계를 진행합니다.
```powershell
copy .env.example .env   # 최초 1회, 이후 .env의 비밀번호를 원하는 값으로 수정
docker compose up -d
docker compose ps        # STATUS가 healthy인지 확인
```

> `.env`의 비밀번호는 MySQL 볼륨이 **처음 생성될 때만** 적용됩니다.

## 2. IntelliJ에서 애플리케이션 실행

1. `Run > Edit Configurations...`에서 `TicketReservationApiApplication` 설정을 엽니다.
2. **Environment variables**에 `DB_PASSWORD=<.env의 MYSQL_PASSWORD 값>`을 입력합니다.
